An OpenAI-compatible endpoint that routes each request by its model name to the Claude API, the Gemini API or OpenRouter, using provider keys held on the server.

01

Routing

The model field of each request picks the provider. The rules are tried in order and the first match wins.

RuleModel nameProvider and upstream

  1. */*

    contains /

    • openrouter/auto
    • anthropic/claude-sonnet-4-6
    • google/gemini-2.5-flash-lite

    routes to openrouter

    OpenRouter

    Pass-through: the body is forwarded byte for byte, model name included.

    openrouter.ai/api/v1/chat/completions

  2. claude-*

    starts with claude-

    • claude-sonnet-4-6
    • claude-haiku-4-5

    routes to claude

    Claude API

    Translated to the Anthropic Messages API, with automatic prompt caching.

    api.anthropic.com/v1/messages

  3. gemini-*

    starts with gemini-

    • gemini-2.5-flash

    routes to gemini

    Gemini API

    Pass-through to Gemini’s OpenAI-compatible endpoint.

    generativelanguage.googleapis.com/v1beta/openai/chat/completions

  4. *

    anything else

    • gpt-5

    is refused with 400

    Not routed: model_not_routable

    The error message lists the three rules.

  • Rule 1 is tried first, so anthropic/claude-sonnet-4-6 goes to OpenRouter, not to the Claude API.
  • Names are not checked against a list: any name the provider accepts works. GET /v1/models lists the models the router has metadata and prices for.
  • Claude requests are translated rather than passed through, so response_format with a JSON schema becomes structured output. A feature with no faithful translation, such as response_format: json_object, is refused with 400 unsupported_parameter.
  • A model name is 1 to 128 characters from A-Z a-z 0-9 . _ : / @ + -, starting with a letter or digit; anything else is 400 invalid_model. A routed provider without a key answers 503 provider_not_configured.

02

Quickstart

Point any client that speaks OpenAI Chat Completions at the base URL and give it the router password as its API key. Keep the password in an environment variable; these examples read MROUTER_PASSWORD.

Base URL
https://<this host>/v1
API key
The router password, sent as Authorization: Bearer <password>. No other scheme is accepted. Clients never send provider keys.
Endpoints
  • POST /v1/chat/completions Chat Completions, streaming and non-streaming
  • GET /v1/models Models of the configured providers, with context_length and max_output_tokens when known

Agent clients

  • For agent clients such as Hermes, add a custom OpenAI-compatible provider: the base URL above, the router password as the API key, and any routable model name.
  • GET /v1/models supplies context_length (and max_output_tokens), which agents use to size their context.
  • A broken provider key is a 502, never a 401, so it does not trigger credential rotation. Treat a stream that ends without data: [DONE] as failed.
  • Thinking blocks are not sent back to Claude, so a tool loop with anthropic.thinking on can be refused on a later turn. Leave thinking off for tool loops; reasoning_effort alone is fine.

03

Behavior

  1. Only the body reaches the provider.

    The upstream request carries content-type, the provider’s key and the router’s user-agent. Nothing from the client’s headers is forwarded, and provider redirects are never followed. Request bodies are limited to 4 MiB, the upstream timeout is 295 s including the stream, and a client disconnect aborts the upstream request.

  2. Streaming is relayed as it arrives.

    With stream: true the response is text/event-stream and events are passed on as the provider produces them, without buffering. A completed stream ends with data: [DONE]. A stream that fails after its 200 status ends with one error event and no [DONE].

  3. Usage and cost are recorded per model.

    After each response, or at the end of a stream, the router records requests, errors and tokens per UTC day, provider and model. Each request’s cost is exact (reported by the provider, as OpenRouter does), estimated (tokens times the router’s dated price table) or unknown (no price for the model, or incomplete or missing usage). Unknown costs are never counted as zero: a total that includes them is marked partial and is a lower bound.

  4. Provider errors stay errors.

    A failure is never answered with a 2xx. It comes in the OpenAI error envelope, typed gateway_error when the router refused the request and upstream_error when the provider failed; upstream errors name the provider and, when it answered, its upstream_status. An OpenRouter 200 whose body is an error becomes an error response.

  5. A provider key failure is 502, not 401.

    When a provider rejects the router’s key, the answer is 502 provider_auth_failed. A 401 always means the router password, so clients that rotate credentials on a 401 are not misled.

  6. Wrong passwords slow down, then block.

    From the second wrong password in an hour, the source must wait before its next attempt: 250 ms, doubling with each failure up to 30 s. The eighth blocks the source for one hour, even for the right password, and each repeated block doubles, up to 24 hours. A source is one IPv4 address or one IPv6 /64. The counters live in the shared store, so the limits hold across all instances; when the store is unavailable, requests are refused with 503, not let through. These are the defaults.

  7. Prompts, keys and the password are never logged.

    Request bodies, prompts, completions, request headers, the router password and provider keys are never written to logs, events or the store. Each request leaves one log line of allowlisted fields: request id, route, method, status, provider, model, timings, error code and a cold-start flag. Error messages are scrubbed of anything key-like.

  8. Provider keys are encrypted at rest.

    A key set with mrouter keys set is checked with the provider first (no tokens are spent) unless --no-verify is given, and is stored only as AES-256-GCM ciphertext under a key derived from the server secret. It overrides the key in the deployment’s environment. No route returns a key, a prefix or a fingerprint.

  9. Claude requests get prompt caching automatically.

    The router adds cache_control: {"type": "ephemeral"} to each Claude request, so the longest reusable prefix is cached. Send the header x-router-cache: off to turn it off for one request, or replace it with anthropic.cache_control. Prompts shorter than the model’s minimum cacheable length are simply not cached.

04

CLI

mrouter is the command-line client. It logs in, manages the provider keys stored on the router, sends prompts, runs smoke tests, and shows usage, cost and recent errors. It needs Node.js 24 and nothing else.

Install
npm install -g . from a checkout of github.com/mchen04/michael-router
Global flags
--url URL, --json, --timeout S, --no-color, -h/--help, --version
Environment
MROUTER_URL sets the router URL (--url takes precedence); MROUTER_PASSWORD overrides the stored password
Exit codes
0 ok, 1 error, 2 usage, 3 router auth or limit, 4 upstream or provider error, 5 network
Secrets
The router password and provider keys are read from a hidden prompt or stdin, never from arguments.

Michael Router is a private service. There is no sign-up and no web login. Access is by password, through the API.
