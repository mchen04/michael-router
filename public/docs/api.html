Use the OpenAI Chat Completions format.

Connection

Base URL
https://michael-router.vercel.app/v1
Authentication
Authorization: Bearer <password>

Set OPENAI_BASE_URL to this URL and OPENAI_API_KEY to your password. SDKs send the Bearer header for you.

Send model and messages to POST /v1/chat/completions.

Automatic selection

Send model: "automatic" for the ordered chain claude-opus-5-5, gpt-6.1-sol, then morph-dsv41flash. Missing keys and active shared provider cooldowns are skipped. Explicit model names bypass cooldowns and never fall back.

Only HTTP 429, exhausted quota or billing, HTTP 500, 502, 503, 504 or 529, provider overload, or a network failure or timeout before commitment can move to the next provider. A configured second key can retry a definitive billing rejection within a step. Each step is visited once; successful work is never retried.

HTTP 400, 404, 413 and 422, other invalid requests, authentication or permission errors, context limits and safety or policy refusals stop the chain. Any successful completion stops it, including normal safety refusals.

Automatic requests share one budget of at most 285 seconds from request entry, including authentication, store reads, billing-key retries and streaming. A new step needs at least 1 second remaining; otherwise it is skipped with deadline_exhausted. Exhaustion returns all_providers_unavailable, or 504 upstream_timeout if the budget runs out during preparation or before a billing-key retry. Explicit model requests keep their 295-second upstream timeout.

Commitment is the first byte written to the client, including a comment, role chunk or tool call. Before that byte, an eligible stream failure can fall back. After it, failure ends the stream with an error event and no [DONE]; it never restarts on another provider.

The router never executes tools. Requests with tools or tool results can fall back only before commitment. A tool call already streamed is never replayed by the router.

A fallback stores a shared provider cooldown from Retry-After seconds or HTTP date. Valid delays are honored in full, with a 1 second minimum. Missing or malformed values use 30 seconds. Extreme values are capped only at the largest representable end time. Contact the owner to clear a stuck cooldown. Explicit model requests are never blocked by cooldowns. Automatic requests try the provider again after expiry. A cooldown read or write failure does not fail a healthy reply.

The body model, stream chunks and x-router-model identify the concrete answering model. x-router-provider identifies its provider. x-router-fallback lists earlier skips, for example claude:rate_limited,openai:cooldown, or is empty when the first model answers. Other reasons are not_configured, quota_exhausted, unavailable and deadline_exhausted.

If every step is unavailable, all_providers_unavailable returns 503, or 429 when every failure was a rate limit. Its message lists all steps and safe reasons. Wait for the returned Retry-After, the soonest known cooldown end in seconds rounded up, or 30 seconds if no cooldown is known. Missing keys do not shorten real cooldowns.

Morph Ultra supplies unmetered included usage, still subject to Morph rate and capacity limits. Group access being free does not make Claude or OpenAI calls free to Michael, the owner.

Reasoning effort

Effort defaults to medium for Claude, OpenAI, and Gemini. Set "reasoning_effort": "low" | "medium" | "high"; higher costs more.

OpenRouter and Morph keep their own defaults.

Streaming

Set stream: true. Read text from choices[0].delta.content as chunks arrive.

Skip empty choices arrays. They can contain usage.

A complete stream ends with data: [DONE]. An error event or missing ending means the reply is incomplete.

Errors and what to do

401 · Password rejected
Stop. Check the password. Repeated failures cause a temporary block.
400 · model_not_allowed
Use a free OpenRouter ID or an allowed Morph Ultra ID.
400 · model_not_routable
Choose a model that matches a routing rule.
Other 400 errors
Fix the JSON or unsupported fields before retrying.
429 · Too many requests
Wait for Retry-After before retrying.
502 · Provider failure
Retry later. For provider_auth_failed, contact the owner. Keep your password unchanged.
503 · Service unavailable
Retry later. For provider_not_configured, choose another provider or contact the owner.
